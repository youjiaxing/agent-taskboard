# 产品壳外观偏好记在 Client，并支持实时跟随系统

每个 Client 只持久化自己的外观偏好：跟随系统、浅色或深色（`system/light/dark`）。第一次启动及缺少主题字段默认跟随系统，随操作系统实时解析为浅色或深色；手动选择另外两项后停止跟随。实际主题只有 `light/dark`，Embedded Terminal 始终使用固定深色，不随产品壳变化。

桌面窗口与 Host 托盘共用 `desktop-client/` 中的偏好；桌面浏览器和手机浏览器分别使用其来源站点的持久存储，不从 Host 快照选择浏览器外观。Client 只把解析后的浅色或深色写入界面，`color-scheme` 与之对应。

可读取设置中主题字段存在但未知或类型错误时，通用回落浅色；不为任何旧值设分支、别名或迁移脚本。仅修正主题，保全语言、远程 Host 及凭据关联、视图与通知等其他有效设置。读取时不立即写盘；后续正常保存只写合法值。整份 JSON 无法解析、其他字段损坏及存储错误沿用既有处理，不扩大为通用数据恢复。`setAppearancePreference` RPC 严格只接受三个合法字符串；缺参、未知值及非字符串报错且不写设置，存储容错不用于请求。

本决策由 [浅色与深色 UI 精修规格 #239](https://github.com/youjiaxing/agent-taskboard/issues/239) 修订，取代 #145 和 #136 中“四项偏好、三种实际主题”及旧主题重置规则。每个 Client 自记、实时跟随系统、无账号级主题的原则保持不变。

## Considered options

| 选项 | 未采纳原因 |
| --- | --- |
| 首次按系统写入一项具体主题，之后不再跟随 | 操作系统变化后产品壳不会同步，且无法表达用户明确选择跟随系统 |
| 保留第三套实际主题 | #239 明确只保留浅色与深色 |
| 外观偏好记在 Host 上并让所有 Client 共享 | 一个 Client 可连接多份 Host，浏览器来源站点也应互不影响 |
| 为旧主题单独迁移或兼容 | 通用字段回退足以覆盖未知主题，不引入特例 |
| 因未知主题重置整份设置 | 会丢失有效语言、连接与其他设置 |
| RPC 复用存储容错 | 请求必须明确合法，非法请求不能修改设置 |
| 让 Embedded Terminal 跟随产品壳 | Agent 官方 TUI 的可读性与颜色语义需要稳定的固定深色画布 |

## Consequences

- Client 组件只消费语义令牌，不按主题名称写业务分支。
- 跟随系统只是一项持久偏好；解析结果属于当前 Client 的即时界面状态，不写入 Host 快照或设置文件。
- 新增主题只增加一组语义令牌，不改变主壳结构或终端配色。
